# Authoring Templates

Template authoring follows a similar process to its predecessor/alternative of legacy expansion rule authoring. 

To create a new sequence template (or to edit existing ones) navigate to the **Sequence Templates** page of Aerie.

<figure>
  <img alt="Aerie UI - Templates Page" src={templatePage} />
  <figcaption>Figure 1: Navigating to the sequence templates page</figcaption>
</figure>

To create a new template, select `New Template`, and provide your template with:
- a name, 
- a language (currently restricted to: `STOL`, `SeqN`, or `Text`, for CSTOL, SeqN, or plaintext respectively), 
- a parcel ID (to get the set of allowed commands), a model ID (to enable access to the activity types), 
- and then the activity type that this template is for. 

To edit an existing template, mouse over it in the table and select the edit button.

<figure>
  <img alt="Aerie UI - Create New Template" src={createNewTemplate} />
  <figcaption>Figure 2: Creating a new sequence template</figcaption>
</figure> 

This editor has autocomplete functionality, whitespace formatting, and error visibility. There is also a panel that describes the available commands, one describing the template, and the ability to switch to editing a different sequence template.

<figure>
  <img alt="Aerie UI - Template Editor" src={templateEditor} />
  <figcaption>Figure 3: Template Editor</figcaption>
</figure>

Finally, you can save your result, and you are now ready to expand using this template.

## Using Mustache functionality

Templating is done in the <a href=https://mustache.github.io/mustache.5.html>Mustache formatting language</a>, more specifically making use of the <a href=https://handlebarsjs.com/guide/>Handlebars API</a>. This templating language allows users to weave variables from _some_ input (more on the input shortly) into a body of text. For example, if I had the following:

**Input**
```
{
  input: "bananas"
}
```

**Template**
```
I like to eat {{ input }}.
```

and compiled these together using Handlebars, I would get as a result:

**Result**
```
I like to eat bananas.
```

This has a lot of utility as far as expanding activities goes, because, as discussed in the [Introduction](./introduction), we can now directly and easily write a sequence with little template expressions that fill in certain mission model properties.

To parrot our earlier example with this context, what was formerly:

```
export default function MyExpansion(props: {
    activityInstance: ActivityType
}): ExpansionReturn {
    const { activityInstance } = props;
    return [
        C.BOOT_COPY_NOR_IMAGE("ZONE_0", "ZONE_1"),
        A('2024-123T00:00:00').AVS_PCE_MEMORY_POKE(activityInstance.attributes.arguments.quantity, "string"),
        C.EP_XFC_LV_CLOSE("XFC_A"),
        C.DP_PRIORITIZE("STRING", activityInstance.attributes.arguments.quantity)
    ];
}
```

Now becomes:
```
C BOOT_COPY_NOR_IMAGE "ZONE_0" "ZONE_1"
A2024-123T00:00:00 AVS_PCE_MEMORY_POKE {{ attributes.arguments.quantity }} "string"
C EP_XFC_LV_CLOSE "XFC_A"
C DP_PRIORITIZE "STRING" {{ attributes.arguments.quantity }}
```

and both compile to:

**Result**
```
C BOOT_COPY_NOR_IMAGE "ZONE_0" "ZONE_1"
A2024-123T00:00:00 AVS_PCE_MEMORY_POKE 5 "string"
C EP_XFC_LV_CLOSE "XFC_A"
C DP_PRIORITIZE "STRING" 5
```

One remaining question is what precisely the structure of the input is. The above example should give a hint at it, but here is the input schema as a whole:
```
{
  id: number;
  simulationDatasetId: number;
  simulationDataset: {
    simulation: {
      planId: number
    }
  };
  attributes: {
    arguments: { ... };
    directiveId: number;
    computed: { ... };
  };
  duration: Temporal.Duration;
  startOffset: Temporal.Duration;
  startTime: Temporal.Instant;
  endTime: Temporal.Instant;
  activityTypeName: string;
}
```

So, to access the activity type name, followed by the end time, and then a computed argument by the name of `quantity`, one could write:

```
CMD {{ activityTypeName }} endsAt={{ endTime }} quantity={{ attributes.arguments.quantity }}
```

The actual compilation of templates is discussed in [Expanding Templates](./expanding-templates).

### In-AERIE Helpers
We also introduce with Mustache formatting the notion of helpers. Mustache helper functions (discussed in-depth in the Handlebars documentation <a href=https://handlebarsjs.com/guide/builtin-helpers.html>here</a>), allow for a user to invoke a function on parameters to produce a specific value. For example, if I had a helper that adds two numbers, then I would have: 

**Input**
```
{
  input: {
    a: 1,
    b: 2
  }
}
```

**Template**
```
I ate {{ add input.a input.b }} bananas.
```

which compiles to:

**Result**
```
I ate 3 bananas.
```

We have defined in AERIE 4 helpers, currently. User-defined helpers do not yet exist, so only these 4 are available at the moment. 

#### `add-time`
This helper allows a user to compute a new time string (that is either STOL or SeqN compatible) from an existing one, and a duration to be added to that time. For example:
**Input**
```
{
  ...,
  startTime: "2024-001T00:00:00",
  attributes: {
    ...,
    arguments: {
      ...,
      growingDuration: "01:00:00"
    }
  }
}
```

**Template**
```
A{{ add-time startTime attributes.arguments.growingDuration }}
```

which compiles to:

**Result**
```
A2024-001T01:00:00
```

#### `subtract-time`
This helper allows a user to compute a new time string (that is either STOL or SeqN compatible) from an existing one, and a duration to be subtracted from that time. For example:
**Input**
```
{
  ...,
  startTime: "2024-001T00:00:00",
  attributes: {
    ...,
    arguments: {
      ...,
      growingDuration: "01:00:00"
    }
  }
}
```

**Template**
```
A{{ subtract-time startTime attributes.arguments.growingDuration }}
```

which compiles to:

**Result**
```
A2023-365T23:00:00
```

#### `formatAsDate`
This helper allows a user to format a date-like string to whatever language is necessary. For example, if I want STOL-like dates (which use `/` instead of a `T`, and include the time zone abbrevriation) but my input is as such:
**Input**
```
{
  ...,
  startTime: "2025-001T00:00:00.00
}
```

then I can write my template as:

**Template**
```
CMD AT={{ formatAsDate startTime }}
```

which provides me with:

**Result**
```
CMD AT=2025-001/00:00:00Z
```

#### `flatten`
This helper allows a user to format arrays correctly. SeqN array formatting looks a little different than conventional array formatting in Mustache/Handlebars, which we illustrate below:
**Input**
```
{
  ...,
  attributes: {
    ...,
    arguments: {
      ...,
      array: [1, 2, 3, 3.5, "string"]
    }
  }
}
```

**Template**
```
Unflattened: {{ firstArraySet }}; Flattened: {{ flatten firstArraySet }}
```

which provides me with:

**Result**
```
Unflattened: 1,2,3.5,string; Flattened: [1 2 3.5 string]
```

### Other Notes

There are some quirks here, which can be uncovered by looking through the Handlebars documentation. For example, one cannot directly write an input that's not in the input object (or in our case, not an existing property of a simulated activity). The following is invalid:

**Input**
```
<empty>
```

**Template**
```
I ate {{ add 1 2 }} bananas.
```

Similarly, if a non-existent argument (or helper) is used in a template expression, nothing shows up in the result:

**Input**
```
<empty>
```

**Template**
```
I work at {{ company }}.
```

(which compiles to):

**Result**
```
I work at .
```
